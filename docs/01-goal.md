# 成长星球 · 项目目标（Goal）

## 1. 一句话描述

为家里两个孩子（10 岁男孩、12 岁女孩）打造一个在 iPad 上像 App 一样使用的 Web 应用「成长星球」：孩子通过学习打卡赚取「星币」（电子记账），再用星币兑换娱乐（看家长精选的短视频）；家长通过后台确认作业、查看孩子的全部行为数据。

## 2. 背景与动机

- 希望把"完成作业、运动、自主学习"变成孩子主动想做的事，而不是被催促的事。
- 希望孩子的娱乐时间是**可控、内容可筛选、需要用努力换取**的。
- 希望家长能低成本地了解孩子每天做了什么，而不是靠反复询问。

## 3. 核心目标

| # | 目标 | 衡量方式（成功标准） |
|---|------|------------------|
| G1 | 学习行为被持续激励 | 孩子每天主动打开并完成打卡；作业按时完成率提升 |
| G2 | 娱乐受控且需要"挣" | 所有短视频均由家长预先放入；观看必须付费，且当天看得越多越贵 |
| G3 | 家长全面可见 | 孩子在应用内的每一个行为都在家长后台可查 |
| G4 | 家长操作轻量（手机上） | 确认一次作业 1 次点击；添加一个视频只需粘贴抖音分享文案 |
| G5 | 孩子愿意用、喜欢用 | 个性化形象、酷炫的领奖动效、集卡收藏带来情绪价值 |
| G6 | 体验像原生 App | 从 iPad 主屏幕启动，全屏无 Safari 地址栏/工具栏 |

## 4. 用户角色

| 角色 | 说明 | 主要场景 |
|------|------|---------|
| 孩子 A | 10 岁男孩 | 打卡、领奖、抽卡、看视频、装扮 |
| 孩子 B | 12 岁女孩 | 同上，形象与动效风格独立 |
| 家长 | 1~2 位 | 确认作业、管理视频、查看数据、调整规则 |

## 5. 范围

### 本期包含
- 孩子端：用户名密码登录、个性化档案（昵称/头像/背景/装扮）、学习打卡、钱包、多邻国式领奖动效、集卡、短视频观看
- 家长端（手机优先）：一键确认作业、游泳例外设置、视频管理（手机上粘贴抖音链接导入）、行为数据看板、账本查看、账号管理
- **金钱体系**：作业/游泳收入、连续达标加成、视频递增计价、家长记录其他收支；钱包可为负数；所有数值后台可配置
- 全量行为埋点并上报家长后台；全程联网，断网即停止娱乐
- PWA 全屏安装到 iPad 主屏幕
- 部署在海外云服务器

### 本期不包含（后续再定）
- 作业驳回、补交
- 每日观看时长上限
- 背单词的具体玩法（本期只占位）
- 更多学习任务类型（目前仅 4 种）
- 更多娱乐类型（目前仅短视频）
- 多家庭/对外发布

## 6. 设计原则

1. **只奖励优秀，奖励坚持**：学校作业必须在截止时间前完成才有奖励；连续达标奖励递增，一旦中断当周加成清零。不展示两个孩子之间的排行对比。
2. **家长是规则的最终决定者**：凡涉及"是否算完成"的，以家长确认为准；规则数值都可在后台调整。
3. **一切可追溯**：每一笔钱的变动都有来源记录，每一个行为都有日志；为保证数据完整，应用必须联网才能使用。
4. **不留刷星币的漏洞**：发币、扣币、抽卡、计时、计次全部以服务端为准。
5. **孩子端简单、华丽；家长端在手机上高效、清晰。**
6. **内容安全**：孩子端不能访问任何家长未放入的外部内容。

## 7. 主要风险

| 风险 | 应对 |
|------|------|
| 抖音下载接口经常变化、可能失效 | 下载器做成可替换模块；失败时支持家长手动上传视频文件兜底 |
| iPad 上孩子可能退出到 Safari 或其他 App | 推荐配合 iPad「引导式访问」；本应用只负责自身内容可控 |
| 孩子找到"刷钱"的漏洞 | 所有金额由服务端计算；需家长确认的任务不由前端直接发钱；首版防刷细则见需求 J 节，发现漏洞再补 |
| 断网导致行为数据缺失 | 断网立即停止娱乐并锁定操作，恢复后补发事件 |
| 海外服务器访问抖音受限 | 部署前实测下载成功率；失败时家长从手机相册上传兜底 |
| 海外服务器在国内访问慢、视频卡顿 | 选香港/新加坡/日本等对国内线路好的机房；视频转码为适合 iPad 的码率 |
| 激励过度变成"无奖励不学习" | 由家长通过后续金钱体系调节；保留"自愿任务"让孩子体验自主 |
